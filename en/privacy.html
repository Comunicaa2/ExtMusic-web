Privacy and security

What ExtMusic stores, who it connects to and how it protects itself. Only facts checked in the code.

Scope: this page summarizes a review of the code of version 1.4.2, done for this website on 2026-11-25. It is not an independent security audit.

1Summary

Table 1. In a few words
QuestionAnswer
Does it need an account?No. The app has no accounts and doesn't ask for personal data.
Does it show ads?No.
Does it send analytics?It includes no analytics or crash-reporting libraries.
Where is my library?On your phone. ExtMusic has no servers of its own.
Who sees what I listen to?The services it connects to in order to work (YouTube, LRCLIB, KuGou and, for updates, GitHub) receive the normal network requests: for example, your IP address and what you search for or play. Each one follows its own privacy policy.

5Technical security

  • HTTPS only. Unencrypted traffic is blocked (cleartextTrafficPermitted="false").
  • System certificates only. The published version does not trust user-installed certificates, which makes intercepting its traffic harder. Development builds do accept them, for debugging.
  • Patched dependencies. The app forces patched versions of two indirect libraries (jsoup and Guava) because of published security advisories.
  • Open source. All the code is on GitHub under GPL-3.0-or-later; anyone can review it.

6Verified updates

The root of trust is the key used to sign the published APKs: the same one Android uses to accept or reject an update. The updater only appears in copies signed with that key (the GitHub ones).

Table 5. What is checked before installing
CheckIf it fails
The release has a single APK, from github.com/Comunicaa2/ExtMusic, between 1 B and 50 MB and with a published SHA-256 fingerprint.Nothing is offered.
The published version is newer than the installed one.Nothing is offered.
The download doesn't exceed the published size and its SHA-256 matches.It is deleted: «La descarga no coincidía…» (the download didn't match).
Before offering to install it: same package, higher version number and the same signature as the installed app.It is deleted: «La APK no era válida…» (the APK wasn't valid).
When you tap Install everything is checked again; then Android verifies signature and version once more.The installer doesn't open.

Covered threats

  • An APK altered on its way to you.
  • A fake release on a compromised GitHub account: without the signing key, no APK can pass.
  • Cut-off or interrupted downloads.
  • Going back to an older version.
  • Copies with a different signature.

Not covered

  • Whoever controls the GitHub account could hide a new version.
  • Or put fake text in the release notes. That's why they are shown as plain text, without links.

7This website
